# gateway 生产部署与接入新服务

> 快速上手手册。机制详解见 `docs/项目分析与执行链路.md`，权威约定与常量见仓库根 `AGENTS.md`。

---

## 1. 生产跑什么

| 入口 | 生产运行 | 说明 |
|---|---|---|
| `cmd/gateway` | ✅ 唯一常驻 | 业务口 `18080` 走七级流水线；管理口 `18081`（`admin_listen_addr`）提供 `/metrics`、`/debug/logs`、`/readyz`，**无鉴权，必须只对内网/回环开放** |
| `cmd/statestore` | ⚠️ 仅多副本时 | 共享限流桶与熔断状态的参考实现，`18090`。**无鉴权、状态在内存**——只开内网，生产建议按同样协议换 Redis 等实现 |
| `cmd/backend` | ❌ | 演示替身上游，生产被真实业务服务顶替（语言不限，网关只认 `host:port`） |
| `cmd/hashring` | ❌ | 离线测量工具 |

![生产部署拓扑](images/生产部署拓扑与入口职责.png)

配置优先级：**环境变量 > `GW_CONFIG` 指向的 JSON > 内置默认值**。启动横幅打印配置来源；配置校验不过直接**启动失败**（30+ 类校验，这是特性）。

密钥用环境变量注入：`GW_JWT_SECRET` / `GW_API_KEY`（另有 `GW_LISTEN_ADDR` / `GW_ADMIN_LISTEN_ADDR` / `GW_TRUSTED_PROXIES`）。

## 2. 接入一个新的后端服务

推荐用 JSON 配置文件（不用重新编译）；也可改 `internal/config/config.go` 的 `defaultRoutes()` / `defaultServices()` 后 `make build` 重启。

注意：**JSON 里的 `routes` / `services` 是整体替换，不是合并**——写了就要写全；时长写字符串 `"2s"`；字段名拼错会启动失败；下划线开头的 key 当注释忽略。可直接从 `deploy/config.example.json` 复制。

### 示例：接入 `payment-svc`

```json
{
  "services": {
    "payment-svc": {
      "name": "payment-svc",
      "balance": "round_robin",
      "upstreams": [
        { "addr": "10.0.1.21:8443", "scheme": "https", "weight": 1,
          "tls": { "ca_file": "/etc/gateway/certs/internal-ca.pem", "server_name": "pay.internal" } },
        { "addr": "10.0.1.22:8443", "scheme": "https", "weight": 1,
          "tls": { "ca_file": "/etc/gateway/certs/internal-ca.pem", "server_name": "pay.internal" } }
      ],
      "timeout": "3s",
      "breaker": { "window_size": 10, "fail_ratio": 0.5, "min_requests": 4, "open_for": "3s", "half_open_max": 2 },
      "ejection": { "fail_threshold": 3, "cooldown": "5s" }
    }
  },
  "routes": [
    {
      "name": "payment",
      "host": "api.example.com",
      "path": "/api/payment/",
      "path_type": "prefix",
      "strip_prefix": "/api",
      "upstream": "payment-svc",
      "timeout": "5s",
      "retry": { "attempts": 1, "per_try_timeout": "2s" },
      "auth": { "required": true, "scheme": "jwt" },
      "limit": { "rate_per_sec": 100, "burst": 20 }
    }
  ]
}
```

生效与验证：

```bash
GW_CONFIG=/etc/gateway/config.json ./bin/gateway
# 已在跑：直接覆盖文件，3 秒内热重载，日志出现「配置已热重载: ...」
curl -s 127.0.0.1:18081/readyz   # 列出每个服务的 breaker/upstreams/ejected
```

热重载边界：改 `shared_state` / `listen_addr` / `admin_listen_addr` / `overload` **需要重启**，其余 3 秒内生效；熔断器状态跨重载保留（不会把刚打开的熔断器重置回 closed）。

### 容易配错的地方

- **`breaker.fail_ratio: 0` = 一次失败即熔断**，校验不拦，必须显式给合理值；`ejection.fail_threshold: 0` = 不启用节点摘除（单节点服务就该这样）。
- **重试三原则**（代码里写死）：只重试未写出任何字节的失败、5xx 不重试、默认只幂等方法且请求体为空。写操作开 `allow_non_idempotent` 前必须有自己的幂等键。
- **`scheme: https` 的证书先在测试环境验**：路径写错启动就失败，但 CA/SNI 配错表现为该节点全部 502（`x509: ...`）。IP 直连而证书签域名时 `server_name` 必须显式给。
- **`route.timeout` 写整数会被当纳秒**，务必写 `"5s"`。
- 路由 `upstream` 写错服务名 → 启动失败，好事，不是 bug。

## 3. 多副本部署

多副本**必须**配 `shared_state.url`，否则：限流实际放行量 = 副本数 × 阈值；A 副本熔断不影响 B 副本。配了之后：

- 限流每次判定多一次网络往返（`timeout` 默认 200ms）；熔断是周期拉取（`sync_interval` 默认 1s），副本间生效有时间窗。
- 状态服务读不到时按**降级**处理（限流 `fail_open` 放行、熔断退回本地），把 `gw_shared_state_errors_total` 接进告警，别静默放过。
- `trusted_proxies` / `shared_state` / `overload` 等每实例配置必须一致，否则限流维度分裂。
- 节点级摘除状态与指标仍是**每实例各算**，告警按实例维度看。

## 4. 上线检查清单

- [ ] 密钥从 `GW_JWT_SECRET` / `GW_API_KEY` 注入，配置文件无明文
- [ ] 没有 `prefix /` 的兜底路由（`GET /nope/nothing` 实测返回 404 `route_not_found`）
- [ ] 管理口 `18081` 只对内网/回环开放；业务口 `18080` 上 `/metrics` 实测 404
- [ ] `trusted_proxies` 与真实 LB/CDN 网段逐条对齐（留空 = 不信任 XFF，LB 后限流会退化成 LB 地址）
- [ ] 每个 Service 显式配置 `breaker`（不踩 `fail_ratio: 0` 零值）、按业务配 `ejection`
- [ ] `overload.max_inflight` 用 `scripts/loadtest.py` 找并发拐点取 ~70%；`/healthz` 刻意不参与负载保护
- [ ] `/healthz` 接 liveness、`/readyz` 接 readiness（接反了上游全挂时实例不会摘出）
- [ ] 签发的 JWT 全部带 `exp` 且 ≤24h（否则网关升级后存量令牌立刻 401）
- [ ] 有大文件上传时确认 8MB 请求体上限（`maxBodyBytes`，超限 413）够用；有 SSE 长流确认不被 `WriteTimeout` 掐断
- [ ] 多副本已配 `shared_state` 并接告警；上游 TLS 在测试环境验过；`insecure_skip_verify` 没留在生产配置里
- [ ] 变更后跑 `make test`，需要时 `python scripts/demo_faults.py` / `demo_reload.py` 演练

## 5. 仍开放的能力缺口

- 无服务发现（上游是静态列表，改完热重载生效但仍要人改）；无主动健康探活（只有被动摘除）。
- 无配置中心（只有文件 + 环境变量，无 etcd/Nacos 下发与版本化）。
- 出站 `X-Forwarded-For` 原样透传给上游，未清理。
- 网关自身不终结 TLS（入站明文，靠外层 LB/Ingress）；trace 只透传 W3C `traceparent`，不导出 span。
- 容器 / k8s 清单已就位但未在真实集群验证。
