## 2. 缺陷清单

### 2.1 P0：会造成线上故障 / 能力名不副实（✅ 5 条已全部修复，见各条「修复 / 验证」）

#### P0-1 协议升级（WebSocket）100% 失败，返回 502 ✅ 已修（批次 A）
- **现象**：任何 `Connection: Upgrade` 的请求都被网关答成 `502 Bad Gateway`。
- **证据**：`httptest` 上游正确回 101、客户端经网关发起升级，实测响应行 `"HTTP/1.1 502 Bad Gateway"`。
- **根因**：`gateway.go:114-142` 的 `statusWriter` 只实现了 `http.Flusher`。
  `ReverseProxy` 处理 101 走 `http.NewResponseController(rw).Hijack()`（`reverseproxy.go:838-841`），
  而 Controller 只认 `http.Hijacker` 或 `Unwrap() http.ResponseWriter`（`responsecontroller.go:66-75`），
  两者 `statusWriter` 都没有 → `ErrNotSupported` → 交给 `ErrorHandler` → 502。
- **影响**：`proxy.go` 包注释与 README 宣称的「支持 HTTP/1.1 升级（WebSocket）」**实际不可用**；
  SSE 侥幸能用（`Flush` 被转发了）。这是"文档承诺 > 实现"的典型，比缺功能更糟。
- **修法**：给 `statusWriter` 加 `func (w *statusWriter) Unwrap() http.ResponseWriter { return w.ResponseWriter }`
  （一处解决 Hijack / Flush / SetWriteDeadline 的转发），顺手加 `ReadFrom` 转发以保住 `sendfile` 路径。
- **工作量**：~15 行 + 1 个回归测试（骨架见附录 A）。
- **修复**：`statusWriter` 加 `func (w *statusWriter) Unwrap() http.ResponseWriter`（`internal/gateway/gateway.go:154`）
  —— 一层剥壳同时解决 Hijack / Flush / SetWriteDeadline 的转发；并在 `:158` 加 `ReadFrom` 转发，保住零拷贝路径。
- **验证**：新增用例 `TestWebSocketUpgrade`（`internal/gateway/gateway_test.go`）—— 上游回 101、客户端经网关
  升级，拿到 **101 Switching Protocols**，且升级后双向数据「ping/echo:ping」可通。
  修复前同一场景实测是 `HTTP/1.1 502 Bad Gateway`。

#### P0-2 全仓无 panic 兜底 ✅ 已修（批次 A）
- **证据**：全仓 `recover(` 零命中；`2026-09-30.md` 的 panic 实测记录：进程存活，但客户端拿到
  `HTTP 000` / curl `exit 52`（连接重置），**panic 栈只进 stderr，不进 `/debug/logs` 与 `/metrics`**。
- **影响**：偶发连接重置 + 零可观测性，比进程崩溃更难排查（同一个错误在指标里完全看不见）。
- **修法**：`ServeHTTP` 最外层 `defer` 里 `recover()`：未写响应则 500 + `error="panic"`；已写响应则只记日志。
  配合 P2-5 的指标，panic 计数应单独成一个 counter。
- **修复**：`ServeHTTP` 里新增 ⑦′ panic 兜底 `defer`（`gateway.go:202-218`），**注册在收口 defer 之后**
  （LIFO 下先执行，因此 panic 也会被收口记为一次访问日志）；新增 `observability.Metrics.IncPanic`
  （`internal/observability/observ.go:197`），`/metrics` 新增 **`gw_panics_total`**（`observ.go:251`）。
  顺带把收口里的 `entry.Err = proxy.ErrFrom(r)` 改成「只在真取到上游错误时覆盖」，否则会抹掉 panic 信息。
- **验证**：`TestPanicIsRecoveredAndCounted` —— panic 不逃出 `ServeHTTP`，`/metrics` 出现 `gw_panics_total 1`。
- **边界（必须知道）**：未写响应时会给客户端干净的 500 `internal_error`；**已写响应时只能记日志与指标**
  （状态码已经发出去了，改不了）。

#### P0-3 代理路径没有请求体上限 ✅ 已修（批次 A）
- **证据**：`gateway.go:269` 的 `io.LimitReader(r.Body, maxTranscodeBody)`（1MB）只作用于 **gRPC 转码**分支；
  反向代理分支把 body 直接交给 `ReverseProxy` 流式转发，无任何上限。
- **影响**：单个请求即可打满上游磁盘/内存/带宽，是标准的 DoS 面；生产网关普遍有 body size limit。
- **修法**：路由级 `MaxBodyBytes`（缺省如 8MB），入口 `http.MaxBytesReader(w, r.Body, n)`，超限回 413。
- **修复**：`gateway.go:37` 新增 `maxBodyBytes = 8 << 20`；在**路由匹配之后、鉴权之前**按 `Content-Length`
  快速拒绝（`gateway.go:241-251`），再用 `http.MaxBytesReader` 兜住 chunked / 谎报长度；
  `internal/proxy/proxy.go:105-107` 把 `*http.MaxBytesError` 映射成 **413**（错误码 `body_too_large`，
  消息「请求体超过上限 8388608 字节」）。
- **验证**：raw socket 伪造 `Content-Length: 9000000` → `HTTP/1.1 413`；另有 `TestBodyLimitRejectsOversizedBody`
  与 `TestBodyUnderLimitProxied`（证明未超限流量不受影响）。
- **口径修正（与原审计不同）**：落地的是 **8MB 全局默认**（不是原审计写的"路由级"）；
  「每路由可配」仍属后续工作。

#### P0-4 服务端缺 `ReadTimeout` / `WriteTimeout` ✅ 已修（批次 A）
- **证据**：`main.go:42-47` 的 `http.Server` 只有 `ReadHeaderTimeout: 3s`、`IdleTimeout: 60s`；
  全仓无 `WriteTimeout`/`ReadTimeout`。
- **影响**：① 慢速滴流 body 可长期占住连接与 goroutine（ReadHeaderTimeout 只管头部）；
  ② 响应侧没有兜底写超时（`Service.Timeout` 只约束到上游往返，不含向客户端写回的时间）。
- **修法**：`ReadTimeout` 覆盖 body 读取；`WriteTimeout` 取「最大 `Service.Timeout` + 余量」或改成每路由。
- **修复**：`cmd/gateway/main.go:48` 加 `ReadTimeout: 30 * time.Second`；`:52` 加
  `WriteTimeout: cfg.MaxServiceTimeout() + 15*time.Second`；新增 `config.MaxServiceTimeout()`
  （`internal/config/config.go:19`，取所有服务 `Timeout` 的最大值，含 nil 服务保护，单测 `TestMaxServiceTimeout`）。
- **验证**：编译 + 测试通过；当前配置下 `WriteTimeout = 10s（最大 Service.Timeout）+ 15s = 25s`。
- ⚠️ **取舍（必须知道）**：`WriteTimeout` 会掐断**超过该时长的长连接流式响应（SSE）**；
  要长流需按路由放宽，或用 `http.ResponseController.SetWriteDeadline` 续期。

#### P0-5 JWT 缺 `exp` 视为永不过期 ✅ 已修（批次 A）
- **证据（实测）**：

  | token | 结果 |
  |---|---|
  | 带 `exp`（60s 后过期） | 200 |
  | **不带 `exp`** | **200**（被当成永久有效） |
  | `exp` 已过期 | 401 `凭证已过期` |

- **根因**：`auth.go:133` 是 `if c.Exp > 0 && now > c.Exp` —— `exp == 0` 落进"无过期"分支。
- **影响**：配合硬编码演示密钥，等价于"签一次永久通行、无法吊销、无最大寿命"。
  生产上密钥一旦泄露或内部误签发，没有止损点。
- **修法**：`exp` 缺失直接拒；再校验 `exp - iat <= 最大寿命`（如 24h）；`iat/nbf` 给少量时钟偏移容忍。
- **修复**：`internal/auth/auth.go:32` 新增 `ErrNoExpiry`；`:39` 新增 `maxTokenLifetime = 24 * time.Hour`；
  `VerifyJWT` 里 `exp == 0` 直接拒（`:143-144`）；`iat` 存在时校验 `exp-iat ≤ 24h`（超长 → `ErrTooLongLived`）；
  `SignJWT` 未给 `iat` 时自动补；`Code()`（`:184`）新增机器码 `token_no_expiry` / `token_too_long_lived`。
- **验证**：实测无 `exp` 的 token 由原来的 **200** 变成
  **401 `{"error":"token_no_expiry","message":"凭证没有 exp（必须带过期时间）"}`**；
  `auth_test.go` 有 `TestVerifyJWTExpiryPolicy`（正常 / 无 exp / 已过期 / 寿命超 24h）与 `TestVerifyJWTNotYetValid`。
- **口径（诚实说明）**：`iat` 缺失时**无法判断寿命**（JWT 规范本身不强制 `iat`），此时只由 `exp` 兜底。

### 2.2 P1：能力缺失 / 结构性偏离

| # | 缺陷 | 证据 / 坐标 | 影响与修法 |
|---|---|---|---|
| P1-1 | **无配置校验**，错误配置只能运行期暴露 | `gateway.New` 只调 `router.New`（只验正则）；`Upstream` 指向不存在的服务要到请求时才 500 `bad_config`（`gateway.go:226`） | 启动即失败才是标准做法。加 `config.Validate()`：路由重名/同 Host+Path 重复、Upstream 服务不存在、`Transcode` 必须指向 `GRPC:true` 节点、`MinRequests ≤ WindowSize`、`Limit` 非负、`StripPrefix` 必须以 `/` 开头 |
| P1-2 | **无节点级健康与摘除** | `balancer.go:147` 的 `least_conn` 只数在途，不看失败；`roundRobin` 更不看 | 一个坏节点会持续吃掉 1/N 流量，直到**整个服务**熔断（熔断粒度是服务，见 `breaker` 包注释）。标准网关有被动离群摘除：给节点加失败计数 + 冷却窗，摘掉后再半开探测 |
| P1-3 | **限流 IP 维度用 `RemoteAddr`** | `gateway.go:213` `net.SplitHostPort(r.RemoteAddr)`；`ratelimit.Key` :113 在无身份时用该 IP | 网关在 LB/SLB 后面时 `RemoteAddr` 恒为 LB 地址 → 所有匿名客户端**共用一个桶**（限流形同虚设），而且这与本项目文档反复强调的"取真实 IP 必须用 `X-Real-IP`"**自相矛盾**。修法：可信代理白名单 + 从 XFF 右侧可信跳数解析真实 IP |
| P1-4 | **转码连接池持锁拨号** | `transcode.go:51-70`：`Pool.Conn` 在 `p.mu` 内做 `grpc.DialContext(..., WithBlock)`（3s 超时） | 一个慢/黑洞上游会**阻塞所有** gRPC 转码请求（头阻塞），且首次请求把 3s 建连放到请求路径上。修法：per-addr 锁或 `singleflight` + 非阻塞建连（`grpc.NewClient`）|
| P1-5 | **路由匹配每请求编译正则** | `router/route.go:136` `regexp.MatchString("^"+…+"$", got)` 在 `headersMatch` 里按请求执行 | 有通配头规则的请求每次都编译+分配。修法：`router.New` 时预编译到 `compiledRoute`（和 `PathRegex` 一样） |
| P1-6 | **管理面与业务面同端口同 Handler** | `gateway.go:177-185` 的 `/metrics`、`/debug/logs` 排在路由与鉴权**之前** | 已知问题（无鉴权），但修法应是**结构性**的：独立 `AdminListenAddr`（只监听 127.0.0.1/内网）+ 独立 mux，业务面彻底看不到管理端点；顺带把 `/readyz`（含上游探测）放管理面 |
| P1-7 | **无每路由超时 / 无重试** | 超时挂在 `Service.Timeout`；全仓无 retry | 标准网关支持 per-route timeout / retry（幂等白名单 + 重试预算）。当前一个服务下的所有路由共享同一超时，且一次失败即失败（对幂等 GET 尤其浪费） |
| P1-8 | **上游只支持 http** | `proxy.go:46` `url.Parse("http://" + upstream.Addr)`；`config.Upstream` 无 `Scheme` 字段 | 无法接 HTTPS/mTLS 上游。修法：`Upstream.Scheme` + `TLSConfig`（含 SNI、InsecureSkipVerify 开关、客户端证书） |
| P1-9 | **访问日志只留 8 位 trace** | `observ.go:75` `"trace=" + Short(e.TraceID)`，`Short` :121 截到 8 字符 | 响应体里给客户端的是 32 位全量 trace，日志里只有 8 位 → 排障只能按前缀猜、且大流量下有碰撞。修法：日志同时写全量与短前缀（或全量，短前缀只用于人眼扫） |

### 2.3 P2：安全加固 / 可观测性 / 性能细节

| # | 缺陷 | 证据 / 坐标 | 说明 |
|---|---|---|---|
| P2-1 | `Bearer` 前缀大小写敏感 | 实测 `bearer xxx` → 401 `凭证格式错误` | RFC 7235 规定 scheme 大小写不敏感；`auth.go:71` 的 `strings.CutPrefix(raw, "Bearer ")` 应改为大小写不敏感匹配 |
| P2-2 | 未剥离 `Forwarded`（RFC 7239）等头 | `proxy.go:33-35` 的 `InternalHeaders` 只有 5 个 | 后端若读 `Forwarded` 会被客户端伪造；建议补 `Forwarded`、`X-Original-URL`、`X-Rewrite-URL`（nginx 系注入面）|
| P2-3 | 哈希键由客户端头决定 | `config.go:110` `HashKeyFrom: "X-User-Id"` + `gateway.go:245-247` 直接读入站头 | 客户端可自选落点（亲和性/缓存投毒面）。应改为「鉴权后的身份（JWT `sub`）」而非入站头；当前 `X-User-Id` 虽在 `InternalHeaders` 里被剥掉（后端看不到），但**路由决策已经按它做了** |
| P2-4 | Transport 未设 `MaxConnsPerHost`，也未设 `DisableCompression` | `proxy.go:81-92`（有 MaxIdle*/Dial/Idle 超时，无 Conn 上限） | 单个上游可被打开无限连接；`DisableCompression` 不设会让 Go 的 Transport 自行加 `Accept-Encoding` 并透明解压，语义容易和上游/客户端期望错位 |
| P2-5 | 指标无直方图、无 `go_*`/`process_*`，且渲染顺序不确定 | `observ.go:195-243`（latency/limitHits/cbTrips 直接遍历 map 输出） | 分位数跨实例不可聚合（已知）；补 `prometheus/client_golang` 直方图 + `sort` 输出；panic 计数也应在此暴露 |
| P2-6 | 熔断半开槽位不是 defer 归还 | `gateway.go:231`（Allow）→ :251-256（Pick 失败直接 return，**无 Report**）→ :262（只 defer 了 Done） | 与上轮修的 `Pick/Done` 是**同一类"借还不成对"**。当前不可达（零上游时熔断器不会打开），但一旦引入节点摘除/动态上游就会变成真 bug。建议把 `Report` 也改成 defer 成对 |
| P2-7 | `StripPrefix` 无边界校验 | `proxy.go:53-58` `strings.HasPrefix` + `TrimPrefix` | 路径恰好以 `/api` 开头但不是路径段时（如 `/apifoo`）会被误剥。当前路由自带 `/api/order/` 前缀掩盖了它；通用化前必须加段边界判断 |
| P2-8 | 演示配置自身的两个坑（沿用登记） | `self` 零值 `BreakerConfig`（`config.go:94-97`）、`order-svc` 权重 `3:1:1` 不生效（`:101-103`） | 已在 §8.6 / §8.2 登记，此处只提醒：**示例配置会被抄进生产**，建议示例即正确 |

## 4. 已验证的正面结论（审计也要说做对了什么）

| 结论 | 证据 |
|---|---|
| **JWT 签名校验扎实，无算法混淆** | 实测 5 种攻击形态全部 401：`alg=none`+空签名段、`alg=none`+字面 `none`、只有两段（无签名）、改 payload 不重签、错误密钥。根因是它**根本不看 header 的 `alg`**，固定 HS256 + `hmac.Equal` 恒定时间比较 |
| 过期语义正确 | `exp` 过期 → 401 `凭证已过期`；`nbf` 未生效 → 拒绝 |
| 内部头治理有效 | 入站 `X-Company-Id: 999` 在上游回显里**不存在**（实测）；`X-Real-IP`/`X-Forwarded-Host/Proto` 由网关重写 |
| 上游超时真传播 | `r.WithContext(ctx)`（`gateway.go:286`）+ `ReverseProxy`，实测 504 与 502 可区分 |
| 并发安全无裸共享状态（**读码结论**） | 每个共享结构都有 `Mutex`/`RWMutex`/`atomic`，未发现裸共享状态；`least_conn` 计数 atomic + 锁内 Pick。⚠️ 本机 `-race` 不可用（见 §1），此条**未经检测器验证** |
| 资源惰性创建 | 熔断器/均衡器/代理按需创建并缓存（`gateway.go:78-110`），不预先占资源 |
| 令牌桶工程细节到位 | 惰性补充（无常驻定时器）+ 空闲桶 GC（防内存泄漏） |
| 一致性哈希有实测背书 | 虚拟节点 150/节点、MD5 截断、扩容迁移率都有 `cmd/hashring` 的测量数据 |

## 附录 A：P0-1 的复现与回归测试骨架

审计时用过、验证完已删除（避免把红着的用例留在仓库）。**批次 A 已把它加回仓库并通过**：
即 `internal/gateway/gateway_test.go` 里的 `TestWebSocketUpgrade`（该文件 172 行 / 4 用例），实测 **101**。

```go
// internal/gateway/upgrade_test.go —— 上游回 101，客户端经网关应看到 101（审计当时是 502）
func TestWebSocketUpgrade(t *testing.T) {
    upstream := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        hj, ok := w.(http.Hijacker)
        if !ok { t.Error("上游 ResponseWriter 不是 Hijacker"); return }
        conn, brw, err := hj.Hijack()
        if err != nil { t.Error(err); return }
        defer conn.Close()
        brw.WriteString("HTTP/1.1 101 Switching Protocols\r\nUpgrade: websocket\r\nConnection: Upgrade\r\n\r\n")
        brw.Flush()
        line, _ := brw.ReadString('\n')
        brw.WriteString("echo:" + line) // 验证升级后双向数据仍通
        brw.Flush()
    }))
    defer upstream.Close()

    gw, _ := New(&config.Config{
        Routes: []config.Route{{Name: "ws", Host: "*", Path: "/ws", PathType: config.PathExact, Upstream: "svc"}},
        Services: map[string]*config.Service{"svc": {
            Name: "svc", Balance: "round_robin",
            Upstreams: []config.Upstream{{Addr: upstream.Listener.Addr().String()}},
            Timeout: 5 * time.Second,
            Breaker: config.BreakerConfig{WindowSize: 10, FailRatio: 0.5, MinRequests: 4, OpenFor: time.Second, HalfOpenMax: 1},
        }},
    })
    defer gw.Close()
    front := httptest.NewServer(gw)
    defer front.Close()

    conn, _ := net.Dial("tcp", front.Listener.Addr().String())
    defer conn.Close()
    conn.SetDeadline(time.Now().Add(5 * time.Second))
    conn.Write([]byte("GET /ws HTTP/1.1\r\nHost: gw\r\nConnection: Upgrade\r\nUpgrade: websocket\r\n\r\n"))

    line, _ := bufio.NewReader(conn).ReadString('\n')
    if !strings.Contains(line, "101") {
        t.Errorf("协议升级未成功：%q（期望 101）", strings.TrimSpace(line)) // 当前实测：HTTP/1.1 502 Bad Gateway
    }
}
```

修复方式（`internal/gateway/gateway.go`，`statusWriter` 上）：

```go
// Unwrap 让 http.ResponseController 能拿到原始 ResponseWriter —— ReverseProxy 的
// 协议升级（WebSocket）走 rc.Hijack()，没有这层剥壳就只能拿到 ErrNotSupported（实测变 502）。
```
