```
module gwlab · go 1.26.5 · 唯一第三方依赖 google.golang.org/grpc v1.84.0 · 52 个 .go / 10062 行

TraceID → ① 路由 → ② 鉴权 → ③ 限流 → ③ 熔断 → ④ 选节点 → ⑤ 转换 / ⑥ 转发 → ⑦ 指标 + 日志
          router    auth    ratelimit  breaker   balancer   transcode/proxy   observability
          └──────────────────── 全部由 internal/gateway 装配（唯一装配层）────────────────────┘
          ⑦′ panic 兜底 · 请求体上限 8MB · 读写超时 · JWT 强制 exp
          启动即 Validate · clientip 可信代理链 · lb.Report 节点摘除 · admin 独立端口 + /readyz
          配置外置 + 热重载 · 上游 TLS · 每路由超时/重试 · 共享限流与熔断 · 直方图 + W3C 链路 · 负载保护闸门
```

- **生产只跑一个进程**：`cmd/gateway`（业务端口 `127.0.0.1:18080`，管理端口 `127.0.0.1:18081`）；
  多副本时限流与熔断状态交给 `cmd/statestore`（共享状态服务，默认 `127.0.0.1:18090`）。
- **配置三层来源**：`internal/config/config.go` 内置默认（**9 条路由 / 6 个上游**）→
  `GW_CONFIG` 指向的 JSON → 环境变量，启动期 `Validate()`；改文件后每 **3 秒**热重载。
- **接新后端 = 改一个 JSON**（或仍改 `config.go`），机制代码零改动（见 §5）。
- 状态：`fallback` 已删（404 可达）；`least_conn` 已启用且 Pick/Done 成对；
  审计文档里的 P0 / P1 / P2 / C1~C6 已全部落地；仍开放的见 §6。

| 9 | k8s 清单未在真实集群验证（compose 已实测） | `deploy/k8s/*.yaml` | 本机 Docker Desktop 没有启用 Kubernetes（启用要重启 Docker），只做过离线结构核对；`statestore` 的 key 分片/多副本一致性同样没验过 |
| 10 | **限流阈值改了不刷新已存在的桶** | `ratelimit/limit.go:77-86` | `Bucket(key, p)` 命中已有 key 直接返回旧桶，新 `rate/burst` 要等空闲 3 分钟 GC 或进程（含 `statestore`）重启才生效 —— 容器里改 ConfigMap 热重载后**限流数字看着没变**就是它 |

另有：入站仍是明文 HTTP（TLS 由外层 LB/Ingress 终结）、无配置中心（etcd/Nacos 下发）、
`/metrics` 与 `/debug/logs` 自身无鉴权（靠管理端口隔离兜住）、API Key 仍可走 `?api_key=` query。

## 8. 进程与端口拓扑

```
                客户端 / curl / Python / 浏览器
                        │
                        ▼
        ┌───────────────────────────────────────────┐
        │  cmd/gateway   127.0.0.1:18080（业务）     │   ← 生产只跑这一个进程
        │  trace → ① ~ ⑦ 七级流水线 + ⑦′ panic 兜底  │
        │  闸门 · 共享限流后端 · 共享熔断采纳协程     │
        └───┬───────────┬───────────┬───────────────┘
            │ HTTP      │ HTTP      │ gRPC (HTTP/2, json codec)
            ▼           ▼           ▼
     backend A/B/C   （同上）      19100  backend A 的 gRPC 端口
     19001/19002/19003
       A 额外开 19100；`?ms=<毫秒>` 延时（≤5s）；/__control?fail=1|0 注入 500

        ┌───────────────────────────────────────────┐
        │  AdminHandler   127.0.0.1:18081（同进程）  │
        │  /metrics · /debug/logs · /readyz         │   ← 业务端口上这三个是 404；
        └───────────────────────────────────────────┘      AdminListenAddr 留空才退回同端口

        ┌───────────────────────────────────────────┐
        │  cmd/statestore   127.0.0.1:18090         │   ← 只在多副本时才需要
        │  POST /ratelimit · POST+GET /breaker      │      复用 ratelimit 的令牌桶
        │  GET /healthz                             │      ⚠️ 无鉴权，不要对外暴露
        └───────────────────────────────────────────┘
```

- **优雅退出**：SIGINT/SIGTERM 后给在途请求 10 秒收尾，两个 server 都 `Shutdown`（`main.go:99-102`）；
  `Gateway.Close()` :133 先停共享状态协程再关 gRPC 池。
- `/healthz` 是路由（`Upstream:"self"`），不是管理端点，也不受闸门限制；`/readyz` 才回答「能不能接流量」。

### 8.1 多副本形态：哪些在进程内、哪些被共享

| 状态 | 单副本（默认） | 多副本（配 `shared_state.url`） |
|---|---|---|
| 限流令牌桶 | 每进程一份 → **放行量 = 副本数 × 阈值** | 判定交给 `statestore`；失败按 `fail_open` 并计入 `gw_shared_state_errors_total` |
| 熔断器状态 | 每进程一份，各学各的 | 本地跳闸→有界队列(64)→POST；周期(1s) GET 采纳 `ForceOpenUntil`；**窗口原始计数不共享** |
| 节点摘除 / 在途计数 | 进程内 | **仍进程内**（各自观测，几秒自愈） |
| 日志 / `gw_*` 指标 | 进程内 | **仍进程内**：看板按副本聚合；旧毫秒分位不可聚合，直方图可以 |
| gRPC 池 / 代理缓存 / 配置快照 | 进程内，热重载原地复用 | 同左（每副本各自轮询 `GW_CONFIG`） |
