```

TraceID → ① 路由 → ② 鉴权 → ③ 限流 → ③ 熔断 → ④ 选节点 → ⑤ 转换 / ⑥ 转发 → ⑦ 指标 + 日志

          └──────────────────── 全部由 internal/gateway 装配（唯一装配层）────────────────────┘
          ⑦′ panic 兜底 · 请求体上限 8MB · 读写超时 · JWT 强制 exp（批次 A）
          启动即 Validate · clientip 可信代理链 · lb.Report 节点摘除 · admin 独立端口 + /readyz（批次 B）
          配置外置 + 热重载 · 上游 TLS · 每路由超时/重试 · 共享限流与熔断 · 直方图 + W3C 链路 · 负载保护闸门（批次 C）
```

- **生产只跑一个进程**：`cmd/gateway`（业务端口 `127.0.0.1:18080`，管理端口 `127.0.0.1:18081`）；
  多副本时限流与熔断状态交给 `cmd/statestore`（共享状态服务，默认 `127.0.0.1:18090`）。
- **配置不再只是 Go 字面量**：`internal/config/config.go` 仍是默认值来源（**9 条路由 / 6 个上游**），
  但 `Load()` 会依次叠加 `GW_CONFIG` 指向的 JSON 文件与环境变量，并在启动期 `Validate()`。
- **接新后端 = 改一个 JSON**（或者仍改 `config.go`），机制代码零改动（见 §5）。
- 状态：`fallback` 已删（404 可达）；`least_conn` 已启用且 Pick/Done 成对；审计里的 **5 条 P0（批次 A）、
  9 条 P1 + 4 条 P2（批次 B）、批次 C 的 8 项结构改造已修**；仍开放的见 §6。

       │                │                │                  │
       ▼                ▼（演示替身）    ▼（离线测量）      ▼（共享状态服务）

 └───────────────────────────────┘              └──────────────────────┘
   │    │    │     │      │       │      │      │
   ▼    ▼    ▼     ▼      ▼       ▼      ▼      ▼
 router auth ratelimit breaker balancer transcode overload  clientip
   │    │    │     │      │       │      │        │          │
   └────┴────┴──┬──┴──────┴───────┴──────┘        │          │
               ▼                                  │          │
     config（叶子：只 import time/标准库）          │          │
                                                 │          │
     overload（叶子：只 import context/errors/sync/atomic）   │
     clientip（叶子：只 import 标准库）◄─────────────────────┘

|---|---|---|
| `config` | —（叶子，只 `time` / 标准库） | 其余 11 个 internal 包 + `cmd/gateway` + `cmd/statestore` |
| `observability` | —（仅标准库） | `proxy`、`gateway`、`cmd/gateway` |
| `clientip` | —（仅标准库，叶子包） | `gateway` |
| **`overload`** | **—（仅标准库，叶子包）** | **`gateway`** |
| `router` / `ratelimit` / `breaker` / `balancer` | `config` | `gateway`（`ratelimit` 另被 `cmd/statestore` 引用） |
| `auth` | `config` | `gateway`、`proxy` |
| `transcode` | `config`（+ grpc） | `gateway` |
| `proxy` | `auth`、`config`、`observability` | `gateway` |
| `gateway` | 上面全部 11 个 | `cmd/gateway` |
| `cmd/statestore` | `config`、`ratelimit` | —（可执行体） |

**单向规则**：`config` / `clientip` / `observability` / `overload` 在底层，机制包之间**不允许互相 import**
（`proxy → auth` 是唯一例外，且方向单一）。`gateway` 是唯一装配层，只被 `cmd/gateway` 引用；
`cmd/statestore` 刻意**不 import `gateway`** —— 它只需要限流桶，装配层不该被第二个入口拖进来。

> ⚠️ **`clientip` 为什么必须是独立叶子包**：`internal/config/validate.go` 也要校验 `TrustedProxies` 的 CIDR，
> 但 `config` 是依赖树最底层，**不能 import `internal/clientip`** —— 所以那一遍 CIDR 解析在 `validate.go:244`
> 自己写了一遍（`parseTrusted`）。这不是重复代码没收拾，而是依赖方向决定的：要么重复十几行解析，
> 要么让 `config` 依赖 `clientip`、把叶子包关系搞成环。
>
> ⚠️ **`cmd/statestore` 为什么复用 `ratelimit`**：共享限流与本地限流的**判定语义必须完全一致**，
> 否则「把限流切到共享状态服务」就变成了一次**语义变更**（阈值行为悄悄变了），
> 而不是单纯把状态挪个地方。所以它直接 `ratelimit.NewLocalBackend()`（`cmd/statestore/main.go:60`）。

> ⚠️ **`lb.Report` 为什么不能省**：只 `Pick`/`Done` 的话，均衡器只知道「谁在忙」，不知道「谁在坏」——
> 一个持续 5xx 的节点会一直吃掉 1/N 流量，直到整个服务被熔断（审计 P1-2）。
> `lb.Report` 是节点级摘除的唯一输入，而 `defer lb.Done` 只管在途计数，两者职责不同、都要有。
>
> ⚠️ **重试为什么只认「没写出任何字节」**：`committed` 由 `sw.wrote` 决定（:635）。
> 一旦上游开始回响应，换节点重来需要把响应缓冲起来（内存代价 + 破坏流式/SSE/协议升级），
> 还可能把已经产生副作用的操作做两次 —— 所以 5xx 与「写到一半失败」都不重试（见 `types.go:43-63`）。

                        │

### 8.1 多副本形态：哪些在进程内、哪些被共享

| 状态 | 单副本（默认） | 多副本（配 `shared_state.url`） |
|---|---|---|
| 限流令牌桶 | 每进程一份（`ratelimit.LocalBackend`）→ **放行量 = 副本数 × 阈值** | 判定交给 `statestore`（`HTTPBackend`）→ 一份桶；失败按 `fail_open` 决策并计入 `gw_shared_state_errors_total` |
| 熔断器状态 | 每进程一份，各学各的 | 本地跳闸 → 有界队列（64）→ POST `/breaker`；周期（默认 1s）GET 采纳 → `ForceOpenUntil`。**滑动窗口原始计数不共享**（各副本流量本来就不同） |
| 节点级摘除 / 在途计数 | 进程内（`balancer/health.go`） | **仍为进程内**（每个副本各自的观测，几秒内自愈） |
| 访问日志 / `gw_*` 指标 | 进程内环形缓冲 + 计数器 | **仍为进程内**：看板要按副本聚合；旧毫秒分位不可跨实例聚合，直方图可以 |
| gRPC 连接池 / 代理缓存 | 进程内，热重载**原地复用**（不重建） | 同左 |
| 配置快照 | `atomic.Pointer[state]`，热重载原子替换 | 同左（每个副本各自轮询自己的 `GW_CONFIG`） |

- **业务端口**（18080）：只有七级流水线；`/healthz` 是**路由**（`Upstream: "self"`），不是管理端点，**也不受闸门限制**。
- **管理端口**（18081）：`/metrics`（全局计数器 + 直方图 + 运行时 + **节点级**三组指标）、`/debug/logs`（最近 50 条访问日志）、
  `/readyz`（就绪检查：任一已被使用过的服务熔断、或所有节点被摘除 → 503）。
- **优雅退出**：收到 SIGINT/SIGTERM 后给在途请求 10 秒收尾，**两个 server 都会 `Shutdown`**（`cmd/gateway/main.go:99-102`）；
  `Gateway.Close()`（`gateway.go:133`）先关 `stop` 让共享状态协程退出，再关 gRPC 池（`wg.Wait()` :136）。
