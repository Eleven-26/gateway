```
                     ▼                  ▼（演示替身，不进生产） ▼（离线）
        ┌────────────────────────────────────────┐
        │   internal/gateway（唯一装配层）        │

              │        │        │        │        │
              ▼        ▼        ▼        ▼        ▼
           router   auth   ratelimit  breaker  balancer   transcode
              │        │        │        │        │           │
              └────────┴────────┴───┬────┴────────┴───────────┘
                                    ▼
                            config（叶子：只 import time）

        proxy ──► auth（取身份 :76）、observability（取 TraceID 头名）
        observability：只依赖标准库，被 proxy / gateway / cmd/gateway 引用
```

| 包 | import 的内部包 | 被谁 import |
|---|---|---|
| `config` | —（叶子） | 其余 8 个 internal 包 + `cmd/gateway` |
| `observability` | —（仅标准库） | `proxy`、`gateway`、`cmd/gateway` |
| `router` / `ratelimit` / `breaker` / `balancer` | `config` | `gateway` |
| `auth` | `config` | `gateway`、`proxy` |
| `transcode` | `config`（+ grpc） | `gateway` |
| `proxy` | `auth`、`config`、`observability` | `gateway` |
| `gateway` | 上面全部 9 个 | `cmd/gateway` |

**单向规则**：`config` 永远在最底层，机制包之间**不允许互相 import**（`proxy → auth` 是唯一例外，且方向单一）。

## 3. 请求链路地图（`ServeHTTP` 逐行坐标）

全部在 `internal/gateway/gateway.go` 的 `ServeHTTP` :182 内，按执行顺序：

| 阶段 | 代码坐标 | 结局 / 产物 |
|---|---|---|
| 入口 | :183-188 | `EnsureTraceID` 复用或生成 `X-Trace-Id`；`statusWriter` 包住 `w`；inflight +1 |
| **⑦ 收口（defer）** | :190-199 | 回填状态码/耗时/字节数、`Err`（**只在真取到上游错误时覆盖**，以免抹掉 panic 信息）、`Observe`、`alog.Write` |
| **⑦′ panic 兜底（defer）** | :202-218 | `recover()` → `gw_panics_total` +1、`Err=panic: …`、栈打到 stderr；**未写响应则 500 `internal_error`**（注册在收口之后 → LIFO 下先执行） |
| 网关自带端点 | :221-230 | `/metrics`（含 `gw_panics_total`）→ 200；`/debug/logs` → 200 JSON（⚠️ 排在路由与鉴权**之前**） |
| **① 路由** | :232-239 | 未命中 → 404 `route_not_found`；命中则记 `Route`/`MatchWhy` |
| **请求体上限** | :241-251 | `Content-Length > maxBodyBytes(8MB)` → **413 `body_too_large`**；否则 `MaxBytesReader` 兜住 chunked/谎报长度 |
| 自答短路 | :253-256 | `Upstream == "self"` → 200 `{"status":"ok"}` |
| **② 鉴权** | :258-266 | 401 `unauthorized`（含 `token_no_expiry`/`token_too_long_lived`）/ 403 `forbidden` |
| **③ 限流** | :268-278 | 拒 → 429 `rate_limited`，带 `Retry-After`、`X-RateLimit-Policy`；key = 用户优先，回落 IP |
| 服务解析 | :281-285 | 上游名未定义 → 500 `bad_config` |
| **③ 熔断** | :287-297 | `cb.Allow()` 失败 → 503 `circuit_open`（快速失败） |
| **④ 选节点** | :299-308 | `hashKey` = `Service.HashKeyFrom` 指定的头，缺省用 client IP；无节点 → 503 `no_upstream` |
| **④ 收尾：`defer lb.Done`** | :315-319 | 与 `Pick` 成对归还计数（`least_conn` 靠它）；用 defer 让 ⑤/⑥ 两条分支都能「有借有还」 |
| 超时注入 | :322-323 | `context.WithTimeout(ctx, svc.Timeout)` —— 超时**由 config 的 Service.Timeout 决定** |
| **⑤ 协议转换** | :325-340 | 读体上限 1MB；成功 → 200 `{"code":0,…,"via":"grpc"}`；失败 → 502 `grpc_error` + `cb.Report(false)` |
| **⑥ 反向代理** | :342-349 | `proxyFor(...).ServeHTTP`；上游 502/504、**超限 413** 由 `proxy.go:94-118` 决定；`cb.Report(status<500)`；恰好打开熔断则 `IncTrip` |

**辅助结构**：`statusWriter` :117（捕获状态码/字节数、转发 `Flush`/`Unwrap`/`ReadFrom`）、`writeJSON` :167、`fail` :173。
**惰性工厂**：`breakerFor` :78（key=服务名）、`balancerFor` :89、`proxyFor` :100（key=`name|addr|strip`）—— 热重载坑点来源（`AGENTS.md` §4）。

## 7. 实测证据（2026-09-30）

环境：`bin/gateway` + 三个 `bin/backend`（19001/19002/19003，A 另开 gRPC 19100）本机运行；
Python `urllib`/socket 探针 + Go `httptest` 测试；`gofmt`/`go vet`/`go test ./...` 全绿。

**批次 A（5 条 P0）**

| 验证项 | 方式 | 实测结果 |
|---|---|---|
| WebSocket / 协议升级 | `TestWebSocketUpgrade`（上游回 101，客户端经网关升级） | 修复前 `HTTP/1.1 502 Bad Gateway` → 修复后 **101**，且升级后双向数据可通 |
| panic 兜底 | `TestPanicIsRecoveredAndCounted`（写响应时 panic） | panic 不逃出 `ServeHTTP`；`/metrics` 出现 **`gw_panics_total 1`** |
| 请求体上限 | raw socket 伪造 `Content-Length: 9000000` | `HTTP/1.1 413`「请求体超过上限 8388608 字节」；未超限的请求正常转发（回归用例） |
| 读写超时 | 代码 + 编译/测试 | `ReadTimeout 30s`；`WriteTimeout = max(Service.Timeout)=10s + 15s` |
| JWT exp 强制 | 无 `exp` 的 token 打 `/api/users/42` | 修复前 **200** → 修复后 **401 `token_no_expiry`**；签名类攻击 5 种形态**始终 401** |

**前一轮（least_conn / fallback）**

| 验证项 | 实测结果 |
|---|---|
| 404 可达 | `/nope/nothing`、`/admin/whatever` → 404 `route_not_found` |
| least_conn 并发 | 9 并发 `/slow?ms=1500` → A/B/C = 3/3/3，墙钟 1.52s（串行下限 13.5s） |
| Pick/Done A/B | 占住一个节点 4s + 20 个串行 `/slow?ms=1`：修复版被占节点 **0/20**；去掉 `defer lb.Done` 的对照版 **6/20**（A/B/C=6/7/7） |
| 平局偏置 | 全 0 平局 1000 次 Pick：`777/116/107` → 修复后 999 次 = **333/333/333** |

**测试面**：4 个包 13 个用例（`balancer` 5 / `gateway` 4 / `auth` 3 / `config` 1）。

**本机口径（踩过的）**：沙箱受限时任何命令都起不来（`pwsh` 退出码 `0xC0000142`，非文件权限问题，切完全权限即恢复）；
长驻进程用 `Start-Process -PassThru -RedirectStandardOutput` 分离启动；
`Get-Content` 按 ANSI 解码 UTF-8 会读坏源码（用 `[System.IO.File]::ReadAllText($p, UTF8)`）；
`go test -race` 在本机不可用（`CGO_ENABLED=0` 且无 gcc），竞态检测只能在 CI 跑。
