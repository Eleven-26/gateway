## 2. 依赖地图

```
                 cmd/gateway        cmd/backend        cmd/hashring
                     │                  │                   │
                     ▼                  ▼（演示替身，不进生产） ▼（离线）
        ┌────────────────────────────────────────┐
        │   internal/gateway（唯一装配层）        │
        └────────────────────────────────────────┘
              │        │        │        │        │
              ▼        ▼        ▼        ▼        ▼
           router   auth   ratelimit  breaker  balancer   transcode
              │        │        │        │        │           │
              └────────┴────────┴───┬────┴────────┴───────────┘
                                    ▼
                            config（叶子：只 import time）

        proxy ──► auth（取身份 :76）、observability（取 TraceID 头名）
        observability：只依赖标准库，被 proxy / gateway / cmd/gateway 引用
```

| 包 | import 的内部包 | 被谁 import |
|---|---|---|
| `config` | —（叶子） | 其余 8 个 internal 包 + `cmd/gateway` |
| `observability` | —（仅标准库） | `proxy`、`gateway`、`cmd/gateway` |
| `router` / `ratelimit` / `breaker` / `balancer` | `config` | `gateway` |
| `auth` | `config` | `gateway`、`proxy` |
| `transcode` | `config`（+ grpc） | `gateway` |
| `proxy` | `auth`、`config`、`observability` | `gateway` |
| `gateway` | 上面全部 9 个 | `cmd/gateway` |

**单向规则**：`config` 永远在最底层，机制包之间**不允许互相 import**（`proxy → auth` 是唯一例外，且方向单一）。
如果发现 `breaker` import 了 `balancer` 之类，就是走反了 —— `gateway` 才是唯一可以同时看到所有机制的地方。

## 3. 请求链路地图（`ServeHTTP` 逐行坐标）

全部在 `internal/gateway/gateway.go` 的 `ServeHTTP` :159 内，按执行顺序：

| 阶段 | 代码坐标 | 结局 / 产物 |
|---|---|---|
| 入口 | :160-165 | `EnsureTraceID` 复用或生成 `X-Trace-Id`；`statusWriter` 包住 `w`；inflight +1 |
| **⑦ 收口（defer）** | :168-174 | **任何分支都会执行**：回填状态码/耗时/字节数、`entry.Err = proxy.ErrFrom(r)`、`metrics.Observe`、`alog.Write` |
| 网关自带端点 | :177-185 | `/metrics` → 200 `text/plain`；`/debug/logs` → 200 JSON（⚠️ 排在路由与鉴权**之前**） |
| **① 路由** | :188-193 | 未命中 → 404 `route_not_found`（**fallback 删除后才真正可达**）；命中则记 `entry.Route`/`entry.MatchWhy` |
| 自答短路 | :196-199 | `Upstream == "self"` → 200 `{"status":"ok"}`（不过鉴权/限流/熔断/选节点） |
| **② 鉴权** | :202-209 | 失败 → 401 `unauthorized` / 403 `forbidden`（`auth.Status`/`auth.Code`）；成功把 `Identity` 塞进 context |
| **③ 限流** | :212-222 | 仅当 `Route.Limit.RatePerSec > 0`；拒 → 429 `rate_limited`，带 `Retry-After`、`X-RateLimit-Policy`；key = 用户优先，回落 IP |
| 服务解析 | :224-228 | 上游名未定义 → 500 `bad_config`（:226，消息含未定义的服务名） |
| **③ 熔断** | :231-240 | `cb.Allow()` 失败 → 503 `circuit_open`（快速失败，不再选节点） |
| **④ 选节点** | :243-257 | `hashKey` = `Service.HashKeyFrom` 指定的头，缺省用 client IP；无节点 → 503 `no_upstream` |
| **④ 收尾：`defer lb.Done`** | **:257-262** | 与 `Pick` 成对归还计数；`least_conn` 完全靠这对调用 —— 用 defer 是为了让 ⑤/⑥ 两条互斥分支都能「有借有还」 |
| 超时注入 | :265-266 | `context.WithTimeout(ctx, svc.Timeout)` —— 超时**由 config 的 Service.Timeout 决定**，不在 proxy 里 |
| **⑤ 协议转换** | :268-283 | 读体上限 1MB（:34）；成功 → 200 `{"code":0,"data":…,"via":"grpc"}`；失败 → 502 `grpc_error` + `cb.Report(false)` |
| **⑥ 反向代理** | :286-292 | 交给 `proxyFor(svc, up, StripPrefix)`；上游 502/504 由 `proxy.go:94-112` 产生；`cb.Report(status < 500)`；本次请求恰好打开熔断则 `metrics.IncTrip` |

**辅助结构**：`statusWriter` :114（捕获状态码/字节数、转发 `Flush` 以支持 SSE）、`writeJSON` :144、`fail` :150（统一错误体 `{error, message, trace}`）。
**惰性工厂**：`breakerFor` :78（key = 服务名）、`balancerFor` :89（key = 服务名）、`proxyFor` :100（key = `name|addr|strip`）—— 热重载时这三个 map 是坑点来源（见 `AGENTS.md` §4）。

## 7. 本轮实测证据（2026-09-30）

环境：`bin/gateway` + 三个 `bin/backend`（19001/19002/19003，A 另开 gRPC 19100）本机运行，Python `urllib` + 线程池压测（`--noproxy` 等价写法）。

| 验证项 | 命令 / 方式 | 实测结果 |
|---|---|---|
| 404 可达（③ 删除 fallback） | `GET /nope/nothing`、`GET /admin/whatever` | 404 `{"error":"route_not_found","message":"没有匹配的路由","trace":"…"}`（删 fallback 前会被 order-svc 静默吃掉 → 200） |
| order 路由未受影响 | `GET /api/order/list` 带 `Host: api.example.com` | 200，`{"backend":"A",…}`；不带该 Host → 404（作用域如实生效） |
| least_conn 生效 | 9 个并发 `GET /slow?ms=1500` | 分布 A=3 / B=3 / C=3，墙钟 1.52s（串行下限 13.5s） |
| **Pick/Done 配对（A/B）** | `?ms=4000` 占住一个节点 → 20 个串行 `GET /slow?ms=1` | 修复版：被占节点 **0/20**，另两个节点 10/10；对照版（`go build -overlay` 去掉 `defer lb.Done` 那行，仓库源码未改）：被占节点 **6/20**，A/B/C=6/7/7（≈轮询） |
| 平局偏置修复 | `go test ./internal/balancer/ -run Tie -v` | 全 0 平局 1000 次 Pick：修复前 a=777/b=116/c=107（78% 砸首节点）→ 修复后 999 次 = 333/333/333 |
| 静态检查 | `gofmt -l .` / `go vet ./...` / `go test ./...` | 均干净/通过；`balancer` 包 5 个测试通过 |

**为什么必须并发 + A/B 才测得出来**：串行请求时在途数恒为 0，`least_conn` 每次都从全 0 平局开始 —— 而平局轮转本身是公平的，恰好掩盖「没有 Done」；单测能钉住计数不变式，端到端必须靠「先用 `?ms=` 占住一个节点，再打一批请求看是否避开它」的对照实验。

**本机运行口径（本轮踩过）**：
- 沙箱受限时任何命令都起不来（`pwsh` 退出码 `0xC0000142`）；切到完全权限后正常。
- **长驻进程用 `Start-Process -PassThru -RedirectStandardOutput <log>` 分离启动**；本轮用后台任务包装器启动 gateway/backend 时任务立刻「exit 0」且进程不留，`curl` 全部 connection refused。
- PowerShell 5.1 的 `Get-Content` 按 ANSI 解码 UTF-8 源码，会把中文行和换行读坏（行数统计偏小、正则替换失效）；读写 Go 源码一律用 `[System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)`。
