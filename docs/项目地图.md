## 0. 十秒版

```
module gwlab · go 1.26.5 · 唯一第三方依赖 google.golang.org/grpc v1.84.0

TraceID → ① 路由 → ② 鉴权 → ③ 限流 → ③ 熔断 → ④ 选节点 → ⑤ 转换 / ⑥ 转发 → ⑦ 指标 + 日志
          router    auth    ratelimit  breaker   balancer   transcode/proxy   observability
          └──────────────────── 全部由 internal/gateway 装配（唯一装配层）────────────────────┘
```

- **生产只跑一个进程**：`cmd/gateway`（`127.0.0.1:18080`）。
- **配置是 Go 字面量**：`internal/config/config.go` 一个文件 9 条路由 / 5 个上游。
- **接新后端 = 只改 config 一个文件**，不碰任何机制代码（见 §5）。

## 2. 依赖地图

```
                       config（叶子：只 import time）
                          ▲   ▲   ▲   ▲   ▲   ▲
        ┌─────────────────┘   │   │   │   │   └──────────────┐
        │        ┌────────────┘   │   │   └───────┐          │
     router    auth         ratelimit breaker  balancer   transcode ──► grpc（唯一第三方）
        ▲        ▲  ▲            ▲       ▲        ▲          ▲
        │        │  └──────┐     │       │        │          │
        │        │         │     │       │        │          │
        └────────┴─────────┴─────┴───────┴────────┴──────────┘
                              gateway（唯一装配层）
                                   ▲
                                   │
                             cmd/gateway

     observability（只 import 标准库）◄── proxy / gateway / cmd/gateway
     proxy ──► auth（取身份，proxy.go:76）、observability（取 TraceID 头名）
     cmd/backend ──► grpc    cmd/hashring ──► 纯标准库
```

| 包 | import 的内部包 | 被谁 import |
|---|---|---|
| `config` | —（叶子） | 其余 8 个 internal 包 + `cmd/gateway` |
| `observability` | —（仅标准库） | `proxy`、`gateway`、`cmd/gateway` |
| `router` / `ratelimit` / `breaker` / `balancer` | `config` | `gateway` |
| `auth` | `config` | `gateway`、`proxy` |
| `transcode` | `config`（+ grpc） | `gateway` |
| `proxy` | `auth`、`config`、`observability` | `gateway` |
| `gateway` | 上面全部 9 个 | `cmd/gateway` |

**单向规则**：`config` 永远在最底层，机制包之间**不允许互相 import**（`proxy → auth` 是唯一例外，且方向单一）。
如果发现 `breaker` import 了 `balancer` 之类，就是走反了 —— `gateway` 才是唯一可以同时看到所有机制的地方。

## 3. 请求链路地图（`ServeHTTP` 逐行坐标）

全部在 `internal/gateway/gateway.go` 的 `ServeHTTP` :159 内，按执行顺序：

| 阶段 | 代码坐标 | 结局 / 产物 |
|---|---|---|
| 入口 | :160-165 | `EnsureTraceID` 复用或生成 `X-Trace-Id`；`statusWriter` 包住 `w`；inflight +1 |
| **⑦ 收口（defer）** | :168-174 | **任何分支都会执行**：回填状态码/耗时/字节数、`entry.Err = proxy.ErrFrom(r)`、`metrics.Observe`、`alog.Write` |
| 网关自带端点 | :177-185 | `/metrics` → 200 `text/plain`；`/debug/logs` → 200 JSON（⚠️ 排在路由与鉴权**之前**） |
| **① 路由** | :188-193 | 未命中 → 404 `route_not_found`；命中则记 `entry.Route`/`entry.MatchWhy` |
| 自答短路 | :196-199 | `Upstream == "self"` → 200 `{"status":"ok"}`（不过鉴权/限流/熔断/选节点） |
| **② 鉴权** | :202-209 | 失败 → 401 `unauthorized` / 403 `forbidden`（`auth.Status`/`auth.Code`）；成功把 `Identity` 塞进 context |
| **③ 限流** | :212-222 | 仅当 `Route.Limit.RatePerSec > 0`；拒 → 429 `rate_limited`，带 `Retry-After`、`X-RateLimit-Policy`；key = 用户优先，回落 IP |
| 服务解析 | :224-228 | 上游名未定义 → 500 `bad_config`（消息含未定义的服务名） |
| **③ 熔断** | :231-240 | `cb.Allow()` 失败 → 503 `circuit_open`（快速失败，不再选节点） |
| **④ 选节点** | :243-257 | `hashKey` = `Service.HashKeyFrom` 指定的头，缺省用 client IP；无节点 → 503 `no_upstream` |
| 超时注入 | :260-261 | `context.WithTimeout(ctx, svc.Timeout)` —— 超时**由 config 的 Service.Timeout 决定**，不在 proxy 里 |
| **⑤ 协议转换** | :263-278 | 读体上限 1MB（:34）；成功 → 200 `{"code":0,"data":…,"via":"grpc"}`；失败 → 502 `grpc_error` + `cb.Report(false)` |
| **⑥ 反向代理** | :281-287 | 交给 `proxyFor(svc, up, StripPrefix)`；上游 502/504 由 `proxy.go:94-112` 产生；`cb.Report(status < 500)`；本次请求恰好打开熔断则 `metrics.IncTrip` |

**辅助结构**：`statusWriter` :114（捕获状态码/字节数、转发 `Flush` 以支持 SSE）、`writeJSON` :144、`fail` :150（统一错误体 `{error, message, trace}`）。
